# AutoForm AI — Local Developer & Cloud Setup Guide

This guide details how to configure Google Cloud OAuth, database connections, and Razorpay test credentials for AutoForm AI.

---

## 1. Extension Permissions & Hosts Justification (Store Builds)

The production store manifest (`manifest.json`) includes the following minimal permissions:

| Permission / Host | Type | Justification & Usage |
|:---|:---|:---|
| `identity` | Permission | Required for Google Sign-In via `chrome.identity.launchWebAuthFlow` across Chrome, Edge, and Firefox without opening separate tabs. |
| `storage` | Permission | Persists user preferences (pacing, answer tone, persona), memory snippets, and session tokens locally. |
| `unlimitedStorage` | Permission | Removes the standard 5MB browser storage ceiling so resumes (PDF, DOCX, TXT) can be stored locally as Data URLs. |
| `scripting` | Permission | Executes DOM automation and form adapter injection scripts on target web pages. |
| `activeTab` | Permission | Grants transient access to the active tab upon user action (clicking popup buttons or pressing `Alt+Shift+F`). |
| `https://docs.google.com/*` | Host | Grants permission to interact with Google Forms DOM elements and Material Design components. |
| `https://*/*` | Host | Required to detect and fill job applications across third-party ATS platforms (Greenhouse, Lever, Workday, Ashby, Taleo, BambooHR, and generic HTTPS career portals). |
| `https://autoform-ai.onrender.com/*` | Host | Production backend proxy server for AI model routing, form quota sessions, and Razorpay pass verification. |

*(Note: Sensitive permissions like `tabs` and insecure `http://*/*` wildcards have been removed from store builds to ensure swift approval.)*

## 2. Store Draft Uploads & Stable Extension IDs

When publishing to browser extension stores, each store assigns an Extension ID that determines your Google OAuth redirect URI:

### A. Chrome Web Store (Draft Required for New ID)
1. When you pack the extension using `npm run package`, the script generates `dist/autoform-ai-chrome.zip` with the developer `"key"` **automatically stripped**.
2. **Why the key is stripped:** The Chrome Web Store Developer Dashboard does not accept self-generated `"key"` fields in uploaded zip packages. The store automatically generates and signs the package with its own key, assigning a unique Extension ID (e.g. `abcdefghijklmnop...`).
3. **Step 1:** Upload `dist/autoform-ai-chrome.zip` as a draft in the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/).
4. **Step 2:** Before publishing, copy the **Item ID** (the 32-character lowercase string shown in the dashboard URL).
5. **Step 3:** The Chrome OAuth redirect URI is:
   ```text
   https://<CHROME_ITEM_ID>.chromiumapp.org/
   ```

### B. Microsoft Edge Add-ons (Existing Listing)
1. **No new draft needed:** AutoForm AI already has an active, published listing in the [Microsoft Partner Center](https://partner.microsoft.com/dashboard/microsoftedge).
2. Simply copy your existing Edge Extension ID from your Partner Center dashboard overview.
3. The Edge OAuth redirect URI is:
   ```text
   https://<EDGE_PARTNER_CENTER_EXTENSION_ID>.chromiumapp.org/
   ```

### C. Mozilla Firefox (AMO)
1. Firefox Add-ons (AMO) uses the static ID specified in `manifest.json`:
   ```json
   "browser_specific_settings": {
     "gecko": {
       "id": "autoform-ai@whoisadheep.dev",
       "strict_min_version": "140.0"
     }
   }
   ```
2. In Firefox, the redirect URI format generated by `browser.identity.getRedirectURL()` resolves under Mozilla's extension domain, **NOT** `chromiumapp.org`. Use the exact address shown by the Copy button in Options > Server & Connection while running in Firefox.

### 💡 1-Click Redirect URI Discovery Tool
To eliminate guesswork, AutoForm AI provides a built-in discovery tool:
1. Load the extension in your target browser (Chrome, Edge, or Firefox).
2. Right-click the extension icon &rarr; **Options** &rarr; open the **Server** tab.
3. Locate the **Browser OAuth Redirect URI** card.
4. Click **Copy URI** to copy the exact redirect URL generated by that specific browser runtime directly into your clipboard, then paste it into Google Cloud Console!

## 3. Google Cloud OAuth Setup (Step-by-Step)

Follow these exact steps in the [Google Cloud Console](https://console.cloud.google.com/):

### Step 1: Create or Select a Project
1. Go to **Google Cloud Console** > **Select a project** > **New Project**.
2. Name it `AutoForm-AI` and click **Create**.

### Step 2: Configure OAuth Consent Screen
1. Navigate to **APIs & Services** > **OAuth consent screen**.
2. Select **External** and click **Create**.
3. **App Information:**
   - App name: `AutoForm AI`
   - User support email: Select your email.
   - Developer contact email: Enter your email.
4. **Publishing Status (Critical):**
   - Click **Publish App** to switch the status from *Testing* to **In production**.
   - *Why:* Apps left in "Testing" expire refresh tokens every 7 days and only allow pre-approved test emails. "In production" with basic scopes does NOT require Google verification.
5. **Scopes:**
   - Add only basic, non-sensitive scopes:
     - `openid`
     - `.../auth/userinfo.email`
     - `.../auth/userinfo.profile`
   - Do NOT add sensitive or restricted Google Drive or Gmail scopes.

### Step 3: Create OAuth Client IDs & Add Redirect URIs
1. Navigate to **APIs & Services** > **Credentials** > **Create Credentials** > **OAuth client ID**.
2. Select **Web application**.
3. Under **Authorized redirect URIs**, add ALL redirect URIs (one for local development, and one for each production store):
   - **Local Developer Testing:** `https://ieddlclpfmfgiihffbhdmpehapgokgnd.chromiumapp.org/`
   - **Chrome Web Store Production:** `https://<CHROME_ITEM_ID>.chromiumapp.org/`
   - **Edge Add-ons Production:** `https://<EDGE_EXTENSION_ID>.chromiumapp.org/`
   - **Firefox Production:** Use the exact address shown by the Copy button in Options > Server & Connection while running in Firefox.
4. Copy the generated **Client ID** (e.g. `1234567890-abcdef.apps.googleusercontent.com`) and **Client Secret**.

### ⚠️ Critical Note on ID Mismatches
Google Cloud strictly enforces exact string matching for redirect URIs:
- If a user installs AutoForm AI from the Chrome Web Store, the browser computes `chrome.identity.getRedirectURL()` using the Chrome store-assigned ID.
- **If that production ID is not listed under Authorized redirect URIs in Google Cloud Console**, Google will immediately block sign-in with:
  ```text
  Error 400: redirect_uri_mismatch
  The redirect URI in the request does not match the ones authorized for the OAuth client.
  ```
- Therefore, always upload your drafts to Chrome and Edge first, retrieve their assigned IDs, paste both URIs into Google Cloud, and save before publicly launching!

## 4. Server Environment Configuration (`server/.env`)

In the `server/` directory, create a `.env` file (based on `.env.example`):

```bash
# Server Port
PORT=3000

# Database Connection (Supabase / Neon Postgres)
# In Phase 1, provide your real Postgres connection string:
DATABASE_URL=postgresql://postgres:[PASSWORD]@[HOST]:5432/[DB_NAME]
# Optional integration test database:
DATABASE_URL_TEST=postgresql://postgres:[PASSWORD]@[HOST]:5432/[DB_TEST_NAME]

# JWT Secret for Session Tokens
JWT_SECRET=your_super_secret_jwt_key_here_minimum_32_characters

# Google OAuth Credentials
GOOGLE_CLIENT_ID=your_google_client_id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your_google_client_secret

# Razorpay Test / Live Keys
RAZORPAY_KEY_ID=rzp_test_your_test_key_id
RAZORPAY_KEY_SECRET=your_razorpay_secret_here
RAZORPAY_WEBHOOK_SECRET=your_webhook_secret_here

# Enable the hosted Razorpay checkout after the three Razorpay values above
# are real credentials (not placeholders).
PAYMENTS_ENABLED=true

# AI Model API Keys
GROQ_API_KEYS=gsk_...
GEMINI_API_KEYS=AIzaSy_...
OPENROUTER_API_KEYS=sk-or-v1-...
NVIDIA_API_KEYS=nvapi-...

# Admin Dashboard Access Token
ADMIN_STATS_TOKEN=your_secure_admin_token_here
```

## 5. Running Tests Locally

### In-Memory Unit & Mock Tests (Default & CI)
By default, the backend tests use an in-memory database adapter for fast, zero-dependency test execution:
```bash
# Run all unit and mock tests (fast, in-memory)
npm test

# Validate manifest and file assets
npm run validate

# Package production zip bundles in dist/
npm run package
```

### Real PostgreSQL Integration Tests (`DATABASE_URL_TEST`)
To verify quota reservation, transactions, cascade deletion, and concurrency against a real PostgreSQL instance (e.g. Supabase, Neon, or local Docker):

1. Set up a dedicated test database or schema:
   ```bash
   # Using Docker
   docker run --name autoform-postgres-test -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:16-alpine
   ```

2. Run tests with the test connection string:
   ```bash
   DATABASE_URL_TEST="postgresql://postgres:postgres@localhost:5432/postgres" npm test
   ```
   When `DATABASE_URL_TEST` is detected:
   - Tables (`users`, `entitlements`, `payments`, `usage_events`, `daily_solve_counts`) and indexes are automatically created via `initDb()`.
   - Before each test case, tables are cleanly truncated using `TRUNCATE ... CASCADE`.
   - Connections are gracefully terminated on test suite completion.

## 6. Razorpay Dashboard Configuration

Follow these steps in your [Razorpay Dashboard](https://dashboard.razorpay.com/) (start in **Test Mode** first):

### 1. Enable Automatic Payment Capture (CRITICAL)
- Navigate to **Settings** > **Configuration** > **Payment Capture**.
- Set **Default Action** to **Automatically capture payments**.
- *Why:* AutoForm AI's webhook and checkout verification verify captured payments. If manual capture is enabled, transactions will stall in `authorized` status and the Pro pass will not activate until manually captured.

### 2. Configure Webhooks
- Navigate to **Settings** > **Webhooks** > **Add New Webhook**.
- **Webhook URL:** `https://your-production-server.onrender.com/api/v1/payments/webhook`
- **Secret:** Generate a random string (e.g. `openssl rand -hex 24`) and save it as `RAZORPAY_WEBHOOK_SECRET` in your server environment.
- **Active Events:** Check **`payment.captured`** and **`payment.refunded`** (or `refund.processed`).
- Click **Create Webhook**.

## 7. Phased Rollout Order & Backward Compatibility (`LEGACY_ANON_SOLVE`)

To prevent breaking existing users running AutoForm AI v2.0.2 (who do not send authorization headers to `/api/v1/solve`), follow this exact phased rollout order:

1. **Deploy Backend Proxy First with Legacy Flag Enabled:**
   - In your Render / Railway environment variables, configure:
     ```env
     LEGACY_ANON_SOLVE=true
     LEGACY_DAILY_IP_CAP=150
     ```
   - In this mode, unauthenticated solve requests from older extension versions are allowed up to 150 solves/day per IP, clearly logged as `[Legacy Solve] Anonymous solve from IP: ...`.

2. **Publish Extension Update (v2.0.3+) to Web Stores:**
   - Package release zips with `npm run package`.
   - Submit `dist/autoform-ai.zip` to Chrome Web Store, `dist/autoform-ai-edge.zip` to Microsoft Partner Center, and `dist/autoform-ai-firefox.zip` to Mozilla AMO.
   - Pinned extension IDs ensure user settings and local profiles persist smoothly across updates.

3. **Monitor Transition via `/admin/stats`:**
   - Track the adoption of authenticated sessions vs legacy anonymous solves on `/admin/stats`.

4. **Disable Legacy Support (Cutover):**
   - Once the majority of users have updated, set `LEGACY_ANON_SOLVE=false` on your production server.
   - All subsequent solve requests will strictly enforce Google sign-in and server-side monthly quota.

## 8. Post-Deployment Security Reminders

Before going live in production, double-check these two critical security settings:

1. **Disable Diagnostic Debug IP Endpoint (`DEBUG_IP_ENDPOINT`):**
   - The diagnostic route (`GET /api/v1/admin/debug-ip` and `GET /debug-ip`) displays resolved proxy hops and client IP addresses.
   - Once you have tested and verified client IP resolution behind your Render proxy, ensure `DEBUG_IP_ENDPOINT` is removed or set to `false` in your Render environment variables.
   - When disabled, this route returns `404 Not Found` to unauthorized traffic and is only accessible by presenting the secret `X-Admin-Token` header.

2. **Enable Zero Data Retention (ZDR) in the Groq Console:**
   - Go to the [Groq Console](https://console.groq.com/).
   - Navigate to **Settings** / **Organization** &rarr; **Data Controls**.
   - Toggle **Zero Data Retention (ZDR)** to **ON**.
   - *Why:* When ZDR is enabled, Groq immediately deletes operational logs (headers, timestamps, error records) after real-time inference, guaranteeing 0-day retention for all sensitive user resume and form questions.
